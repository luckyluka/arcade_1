# `art/` — the art pipeline

Everything the machine draws comes from here, and **everything here is
generated by code**: a script, a preset, or a text pixmap. No image-model
output, no scanned art, no binary blobs that nobody can regenerate.

Why: the repository has to stay reproducible, auditable and licence-clean.
A sprite that only exists as a PNG is a sprite nobody can change, review
or re-derive. A sprite that a script paints can be re-derived, diffed and
re-graded — and the commit that changed the art says *how* it changed.

## The layout

```
art/
  README.md          this file
  STYLE_TEMPLATE.md  the fields every art set declares
  palettes/*.json    the palette presets (16 entries each)
  ART_LICENSES.md    GENERATED: the provenance of every shipped asset
  px/                text pixmaps (.px) — hand-authored small sprites
  rigs/              rig definitions for the animator
  reports/           the visual reviews (art/reports/<asset>.md)
```

## The rules (every asset, always)

1. **Palette index 0 is transparent.** The key colour (index 0) is the
   *authored* 8-bit value; an art set must not paint it.
2. **At most 15 colours plus transparent per bank.** Index 1 of every
   preset is the **outline** colour — the dark edge that makes a sprite
   readable at 1x. Index 2..15 are the ramp. The outline must be the
   **darkest colour in the bank**: `arc1-art check` infers the outline as
   the darkest colour among the frame's *edge* pixels, so a sprite whose
   fill is darker than its outline fails the check (and a palette whose
   index 1 is only just the darkest will, sometimes, fail it by accident).
3. **Palette entries are distinct as RGB565.** Two colours that collapse
   under the 5/6/5 quantisation are the same colour on the machine; the
   asset compiler rejects them.
4. **One palette bank per asset group** (one character, one tileset, one
   background layer). A second group gets a second bank.
5. **Frames of one state share their size and their baseline.** The
   lowest opaque pixel sits on the same row in every frame of a state, and
   the horizontal anchor on the same column.
6. **A background layer (a tileset) needs no outline ring — and a border
   in a tileset repeats in every cell of the map.** The map importer
   draws the same tile in every cell, so a 1 px border around the tileset
   becomes a grid of lines across the whole world. Make the tiles
   seamless. (`arc1-art check` says "the outline check does not apply"
   for a fully opaque strip: there is no edge to outline.)
7. **Every output file is regenerated by one command and never
   hand-edited.** The generated header is the build truth; the generator
   is the master.
8. **Provenance is recorded per asset** — see
   [docs/art/PROVENANCE.md](../docs/art/PROVENANCE.md) for the schema and
   `art/ART_LICENSES.md` for the generated summary.

## The art pass (Petal Blade)

`make art-petalblade` builds the **rig variant** of Petal Blade: the hero
rebuilt with the rig animator (`art/rigs/samurai.json`), five props from
`.px` pixmaps, the world's own procedural art reused, and
the manifest that ties them together. The variant is a separate game
(`programs/petalblade_rig.c`) with its own golden; the promoted game is
untouched.

The honest comparison — the rig hero against the hand-drawn procedural
one — is in
[docs/experiments/art-pass.md](../docs/experiments/art-pass.md). The
short version: **the rig is better at consistency and editability, worse
at beauty at 28×40 pixels.**

## The library

`art/library/` is the **catalogue of reusable art**: packs, each one a
generator, a manifest fragment, a style sheet and the strips it produces.
`art/library/INDEX.md` is the index; `make art-library` regenerates every
pack and `make art-library-check` proves that a fresh build is byte for
byte the committed one.

```sh
arc1-art merge icons characters village --out game/assets.json
    # compose the packs a game wants into one manifest
```

A pack is *code*, not a folder of PNGs: the generator is the master, the
strips are the build truth, and every asset carries its provenance. A
pack also says how it is meant to be used (its style sheet: the sizes, the
anchor, the collision convention, the palette bank) and carries a review
(`art/reports/<pack>.md`).

**The machine has sixteen palette banks, so a game can use at most
sixteen palette groups.** The library's packs are *alternatives*, not a
set to ship whole: a merge that needs a seventeenth bank fails loudly
("the machine has sixteen palette banks and the merge needs a
seventeenth") rather than quietly overwriting one. Two packs that share
a palette — the same name with the same colours — **share the bank** on
merge, so a face and the body it sits on cost one bank between them and
the merged header's names do not depend on the order the packs were
merged in.

The four packs that are there now are the art the two clean-room rounds
made — the icons, the two rigged characters, the village and the lighthouse
— tidied, with the games' own maps dropped (a map belongs to a game, not
to a library).

## What the checks measure (the numbers, so you do not have to guess)

`arc1-art check` counts these. They are the numbers an artist designs
against — a sprite is "good" by them, so they are written down here
rather than only in `tools/arc1_art/qa.py`:

| check | the rule |
|---|---|
| **colour count** | at most 15 colours plus the transparent key, per frame |
| **palette distinctness** | two colours that collapse under the 5/6/5 quantisation are the SAME colour on the machine — the check fails |
| **orphan pixels** | an opaque pixel with no opaque neighbour (4-connected) is a speck: fail |
| **components** | the silhouette must be ONE connected piece (4-connected); `--allow-components N` for sprites that are legitimately several |
| **baseline** | every frame of a state must stand on the same row (the lowest opaque row) |
| **jitter** | the spread of the bounding boxes' **centres** (not their edges — a swinging limb changes the width, not the anchor). At most 2 px |
| **outline coverage** | the silhouette's **edge** (the opaque pixels that touch a transparent one) must be the outline colour, at least 75 % of them. The outline colour is inferred as the **darkest of the edge pixels** and then used for every frame of the strip; `--outline-colour #RRGGBB` says it outright |
| **fill-to-outline contrast** | the outline's luminance over the mean fill's: at most 0.55 |
| **readability** | the frame's bounding box must be at least 8 px tall |

**The role says what an asset is.** `arc1-art check --role` takes
`sprite` (the default), `tileset`, `layer`, `effect` or `overlay`, and
the role decides which checks apply:

| role | what it is | graded on |
|---|---|---|
| `sprite` | a character or a prop that stands alone | everything: the silhouette, the outline, the baseline, the jitter |
| `tileset` | a set of tiles that repeats | the colours and the distinctness |
| `layer` | a background layer | the colours and the distinctness |
| `effect` | a particle strip | the colours and the distinctness |
| `overlay` | a piece drawn **on top of** another asset — a face on a rig's head | the colours and the distinctness |

The `overlay` role exists for the faces pack: a face has no outline ring
of its own (the head beneath it has one), so grading it as a sprite
would fail it for a rule it does not break.

Two things the checks do **not** apply to:

* a **fully opaque** frame (a background layer, a tileset) has no edge at
  all — the outline and contrast checks do not apply, and the report says
  so (`"outline_check": "does not apply ..."`). A tileset with one
  transparent cell, though, *is* graded like a character; pass
  `--skip-outline` for those;
* a **map**: the strip checks read sprites, so the maps are checked
  separately — `arc1-art check <assets.json> --manifest` reads the
  manifest's maps and reports: a character the map uses with no legend
  entry, a map that draws nothing, a collision layer of the wrong size,
  and (as a **warning**) a tile of the tileset that no character can
  draw — a tile added to the art but not given a character is invisible in
  the game. The composed world is `arc1-art preview <assets.json> --maps`.

**The frame size** (`--frame WxH`) is the size of ONE frame: the strip's
width divided by the frame count. For a one-frame tileset it is the whole
image. A width that does not divide the strip is an error ("the image
holds no frame") — the frame size is the frame, not the strip.

## The visual review

Two halves, and both are needed:

* the **machine half** — `arc1-art check file.png [--frame WxH]` counts
  the colours, the orphan pixels, the components, the baseline, the
  anchor's jitter, the outline coverage and the fill-to-outline
  contrast, and prints a JSON report (exit 1 on a failure);
* the **human half** — [CRITIQUE.md](CRITIQUE.md): the checklist for an
  agent that can see, and the protocol for the review that follows
  (verdict, three observations, what changed, the re-check), written to
  `art/reports/<asset>.md`.

A sprite can pass every check and still be ugly. The checks say the
sprite is *well formed*; the review says whether it is *good*.

## The rig animator

A character is a list of **parts** (a name, a parent, a pivot, a shape, a
colour) and a **pose** (per part: an angle in whole degrees and an
integer offset). Animating is interpolating between poses — linear, with
the result rounded to whole pixels **half away from zero**.

```sh
tools/arc1-art rig art/rigs/humanoid.json --out-dir programs/rig
    # the strips (one per state), the manifest fragment and the sheet
```

`art/rigs/humanoid.json` is the reference preset: idle (4), walk (8),
run (8), jump (1), fall (1), attack (4), hurt (1), dead (1), with an
optional weapon part. The frames of a state share their size and their
baseline, the idle frame's opaque pixels give the collision box, and the
outline pass runs last.

The honest verdict on the result — including what looked wrong and what
was changed — is in **[art/reports/humanoid.md](reports/humanoid.md)**.

## The `.px` format (text pixmaps)

A pixmap is a sprite written as text — the one thing an agent writes
well. The samples live in the library's `icons` pack
(`art/library/icons/pixmaps/`):

```
# name: coin   size: 8x8   palette: warm16   bank: 3
# provenance: {"tool": "agent-authored", ...}
..1111..
.144441.
14455441
14455441
14444441
14444441
.144441.
..1111..
```

* `.` is transparent; `0`-`9` and `a`-`f` are palette indices (index 0
  is the palette's transparent slot, so `.` is the usual way to say it).
* `--` on its own line separates the frames; every frame of a pixmap has
  the declared size.
* The header keys: `name`, `size` (WxH), `palette` (a preset), `bank`
  (0..15), the optional `anchor` (`feet` — the default — or `center`) and
  the optional `provenance` (the JSON block of
  [docs/art/PROVENANCE.md](../docs/art/PROVENANCE.md)).

The tools:

```sh
tools/arc1-art px2assets art/library/icons/pixmaps/*.px --out-dir programs/px
    # the strip PNGs + the assets.json fragment (arc1-assetc compiles it)

tools/arc1-art sheet art/library/icons/pixmaps/coin.px --scale 8 --out preview.png
    # the preview sheet: every frame at 1x and at 8x, with the numbers

tools/arc1-art preview assets.json --out sheet.png --scale 4
    # the contact sheet of a whole manifest — what a review looks at

tools/arc1-art preview assets.json --out world.png --maps
    # the composed WORLD: the manifest's map layers, each on its row

tools/arc1-art check assets.json --manifest
    # the manifest's MAPS: the legend, the tiles, the collision layer

tools/arc1-art info art/library/icons/pixmaps/coin.px
    # what the file declares
```

`make px-samples` regenerates `programs/px/` (the strips, the manifest
fragment and the compiled header — the build truth).

## Writing a generator (and finding the library)

A generator is a python script that paints the assets. It uses the
repository's own drawing library, so it must find it:

```python
import os, sys
HERE = os.path.dirname(os.path.abspath(__file__))
ROOT = os.path.dirname(os.path.dirname(HERE))   # the repo root
sys.path.insert(0, os.path.join(ROOT, "tools"))
from arc1_art import canvas as C
```

That is the shape every generator in the repository uses (see
`programs/petalblade_art/gen_round6.py` and `round4/gen_art.py`). **It
assumes the generator lives in a folder whose parent's parent is the
repository root** — `<repo>/<folder>/<script>.py`, where `<folder>` is
the art's own folder (`<repo>/round6/art/gen_round6.py` is three levels
below the root, and `dirname(dirname(HERE))` lands on it). Two ways out
when the art lives elsewhere:

* keep the generator at that depth (`<repo>/roundN/art/…`), or
* set `ARCADE1_ROOT` and use it instead of the `dirname` guess:
```python
ROOT = os.environ.get("ARCADE1_ROOT") or os.path.dirname(
    os.path.dirname(HERE))
sys.path.insert(0, os.path.join(ROOT, "tools"))
```

A generator that cannot import `arc1_art` dies with
`ModuleNotFoundError: No module named 'arc1_art'` — that is the symptom.

**Two rules that catch everyone out**

* **A tileset is ONE frame.** The map importer takes the tiles from the
  sprite's *first frame*: a tileset image of 72×24 is one frame of three
  24×24 tiles, not three frames. Writing three frames gives a sprite
  that "holds 1 tile".
* **A generator must not allocate without bound.** The canvas is a plain
  list of pixels: a sheet that is a few hundred kilobytes is fine, and one
  that asks for gigabytes will take the machine down with it. Check the
  sheet's size before writing it, and run the generator under a memory
  cap (`ulimit -v`) if you are not sure.

## The pipeline (Wave 7)

| card | tool | what it produces |
|---|---|---|
| 7.2 | `tools/arc1_art/canvas.py` | the drawing library (primitives, ramps, PNG) |
| 7.3 | `tools/arc1_art/pixmap.py` | the `.px` text pixmap format and the sprite lab |
| 7.4 | `tools/arc1_art/rig.py` | the rig animator (parts, keyframes, strips) — see `art/rigs/humanoid.json` and the review in `art/reports/humanoid.md` |
| 7.5 | `tools/arc1_art/ingest.py` | raster ingest — **local only, stdlib only** (PNG, no JPG); see [docs/art/INGEST.md](../docs/art/INGEST.md) |
| 7.6 | `tools/arc1_art/qa.py` | `arc1-art check`: the automated visual checks — with [CRITIQUE.md](CRITIQUE.md) for the human half |

Two decisions shape this pipeline (the owner's, 2026-10-21):

* **Image-model output is never committed.** It may be used locally as a
  style reference; what ships is always code-generated. So the ingest tool
  (7.5) is a *local* helper, not a path into the build.
* **No Pillow, stdlib only.** The ingest tool reads PNG (zlib is in the
  standard library) and nothing else — no JPG.

## The collision layer (a map's "solid")

A map may declare a **collision layer** — the ground the player cannot
walk through. Without it, every game writes its own parallel collision
table, and every game gets it wrong in its own way (the importer dedups
tiles, so a cell's index is not a tile type).

Two forms, both in the map's own entry:

```json
{ "name": "village", "file": "art/village.txt", "tileset": "tiles",
  "tile_w": 16, "tile_h": 16,
  "legend": { "g": 0, "p": 1, "s": 2 },
  "solid": "art/village_solid.txt" }
```

```json
  "solid": { "by_tile": { "g": 0, "p": 0, "s": 1 } }
```

* **a second ASCII layer** (`"solid": "<file>"`): the same size as the
  map, with `#` = solid, `.` = empty, `^` = hazard;
* **a per-tile-type table** (`"solid": {"by_tile": {...}}`): the map's own
  legend characters are the tile types, and the value is 0 (empty), 1
  (solid) or 2 (hazard).

Either way assetc emits `<MAP>_solid[]` (one byte per cell) with
`<MAP>_SOLID_COLS/ROWS` and a `map_ref`, and `programs/asset.h` reads it:

```c
#include "asset.h"          /* map_ref + map_solid */
#include "assets.h"         /* the generated header */

if (map_solid(&village_map, tx, ty) == MAP_SOLID)
    /* do not walk here */
```

Outside the map is **solid**: a player must not walk off the world.

## The manifest, in full

```json
{
  "format": 1,
  "palettes": { "hero16": { "bank": 0, "colors": ["#000000", "..."] } },
  "sprites": [
    { "name": "farmer", "file": "art/strips/farmer.png", "palette": "hero16",
      "frames": 2, "origin": [8, 16], "collision": [4, 10, 8, 6],
      "provenance": { "tool": "procedural", "model": "", "prompt": "...",
                       "seed": 0, "licence": "this repository" } }
  ],
  "animations": [ { "name": "farmer_walk", "sprite": "farmer",
                    "frames": [0, 1], "ms": 130 } ],
  "maps": [ { "name": "village", "file": "art/village.txt", "...": "..." } ]
}
```

* **Every path is relative to the `assets.json` file**, not to the
  repository root: a sprite's `"file"`, a map's `"file"`, and the
  collision layer's file.
* **The PNG's pixels must be EXACTLY the bank's colours.** The default
  quantisation is `"exact"`: a pixel that is not one of the bank's
  colours is a hard error, not a warning. Either paint with the bank's
  own hex values (`canvas.to_strip(frames, palette["colors"], path)`
  does exactly that) or set `"quantize": "nearest"` on the sprite — and
  then the colours are *moved*, not preserved.
* **A legend key is exactly one character** — the map's characters are
  the tile types, so a key of two characters is an error.
* **A map draws a fixed rectangle**, so a world that is taller (or wider)
  than the screen is several maps drawn in world space under one camera:
  one for the sky, one for the cliff, one for the tower, one for the sea.
  Each carries its own palette bank and its own collision layer.
* **A manifest may define its own palette.** The presets are a starting
  point, not a limit: write a new 16-entry bank in the manifest's
  `"palettes"` when the art needs colours no preset holds (four pickups
  want red *and* green *and* gold, and no preset has red and green
  together). A hand-written bank follows the same rules as a preset:
  index 0 is the transparent key, index 1 is the outline (the darkest
  colour in the bank), 2..15 are the ramp, and every colour is distinct
  as RGB565.
* The `origin` and `collision` metadata are the sprite's anchor and
  collision box in the frame's pixels (see `programs/asset.h`).

## How a game gets its art

1. Pick a palette preset and a style sheet (copy `STYLE_TEMPLATE.md`).
2. Draw the sprites — procedurally (7.2), as text pixmaps (7.3) or with
   the rig (7.4).
3. Write the manifest (`assets.json`): palettes, sprites, animations,
   maps, and a `provenance` block per asset.
4. Compile: `arc1-assetc` writes the header the game includes, and
   `art/ART_LICENSES.md` records who made what.
5. Look at it: `arc1-art check` (7.6) plus a human-style review written
   to `art/reports/<asset>.md`.

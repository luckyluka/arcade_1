# ARCADE-1 — Future Ideas

This document contains ideas for the long-term ARCADE-1 ecosystem.

These are **not current requirements** and must not be implemented unless they are explicitly promoted into the development roadmap.

---

## 1. AI-Assisted Game Development

ARCADE-1 should eventually be particularly suitable for AI-assisted game creation.

The goal is that an AI coding agent can create a complete game using the ARCADE-1 SDK without needing to understand the internals of the VM, Libretro, or FPGA implementation.

Conceptually:

```text
AI / Developer
      │
      ▼
  Game source
      │
      ▼
 ARCADE-1 SDK
      │
      ▼
 RISC-V compiler
      │
      ▼
   game.arc1
      │
      ▼
 ARCADE-1 machine
```

The AI should primarily interact with:

- the ARCADE-1 programming API
- game source code
- assets
- level data
- build tools
- test/debug tools

It should not need to modify the machine implementation to create ordinary games.

---

## 2. AI-Friendly SDK

Eventually provide a simple, well-documented SDK with APIs for:

- input
- timing
- drawing primitives
- sprites
- tilemaps
- scrolling
- text
- audio
- game state
- asset loading

Example:

```c
#include <arcade1.h>

int main(void)
{
    arcade1_init();

    while (1) {
        arcade1_input_t input;
        arcade1_input_read(&input);

        /* game logic */

        arcade1_video_clear(BLACK);
        arcade1_rect(player.x, player.y,
                     16, 16, RED);

        arcade1_present();
    }
}
```

The exact API is deliberately undefined until the machine and games demonstrate what is actually needed.

## 3. AI Build → Run → Observe → Fix Loop

Eventually provide tooling that allows an AI agent to autonomously test games.

Possible workflow:

```text
generate code
     ↓
build
     ↓
run ROM
     ↓
inject deterministic input
     ↓
capture frames / state
     ↓
detect failure
     ↓
modify code
     ↓
repeat
```

Determinism is particularly valuable here.

A test could specify:

```text
Input sequence:
RIGHT RIGHT RIGHT A LEFT ...

Frame: 183

Expected:
player.x = ...
player.y = ...
score = ...
```

This would allow reproducible debugging rather than relying on subjective visual testing.

## 4. ARCADE-1 Developer Tools

Possible future command-line tools:

```text
arcade1 build
arcade1 run
arcade1 test
arcade1 debug
arcade1 capture
arcade1 inspect
```

Potential capabilities:

- build a game
- run a `.arc1` ROM
- inject controller input
- capture frames
- inspect CPU registers
- inspect memory
- trace instructions
- trace MMIO
- inspect ROM metadata
- run deterministic regression tests

These tools should remain useful independently of RetroArch.

---

## 5. ROM as the Universal Game Artifact

The long-term goal is for:

```text
game.arc1
```

to be the actual distributable game.

The same ROM should eventually be usable by:

```text
ARCADE-1 C VM
        │
        ├── Ubuntu
        ├── Linux
        └── other desktop systems

RetroArch / Libretro
        │
        └── Android / Google TV

FPGA ARCADE-1
        │
        └── physical console
```

The implementation underneath may differ, but the game artifact remains the same.

---

## 6. AI-Generated Game Library

A possible long-term ecosystem is a collection of small ARCADE-1 games generated by humans and AI.

Examples:

```text
breakout.arc1
tetris.arc1
platformer.arc1
shooter.arc1
puzzle.arc1
racing.arc1
arcade_fighter.arc1
```

The simplicity of the machine should make experimentation cheap.

An AI could potentially generate many small games, compile them, automatically test them, and produce distributable ROMs.

---

## 7. Important Principle

Do not optimize the machine prematurely for AI.

The machine should first become a good, coherent game machine.

AI friendliness should primarily emerge from:

- a small programming model
- deterministic behavior
- clear APIs
- good tooling
- reproducible tests
- simple ROM packaging
- strong documentation

The current ARCADE-1 development roadmap remains authoritative.

Ideas in this document must not cause speculative features to be added to the machine before real games demonstrate that they are necessary.

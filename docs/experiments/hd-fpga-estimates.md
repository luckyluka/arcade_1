# ARCADE-1 — HD experiment: the FPGA-side bill (estimated)

Generated by `experiments/hd/fpga_estimates.py` from
`docs/experiments/hd-measurements.csv`.

**Every number in this file below the inputs is ESTIMATED.**
No FPGA was built and no device was timed. The only measured
quantities are the resolutions (fixed by the experiment) and
`pixels_written_max` (measured on the host, by
`arcade1 run --bench`); both are labelled where they enter.

Measured inputs (this file's only measured numbers):

- host CPU: `Intel(R) Core(TM) i7-6820HQ CPU @ 2.70GHz`
- guests: asteroid_run, brickstorm, flappy, petalblade, shmup
- 600 frames per run, at k = 1, 2, 4
- `W * H` per k, fixed by `-DARCADE1_HD_SCALE=k`
- `pixels_written_max` per k: `run --bench`, `WORK_PX_MAX`,
  the worst frame of the worst guest
- `rom_bytes`: `arcade1 inspect`

## Formulas

```
pixel throughput   = pixels_written_max * 60          px/s
clock @ P px/clk   = (pixels_written_max * 60) / P    Hz
framebuffer RAM    = W * H * 16                      bits
  double buffered  = W * H * 16 * 2                  bits
scan-out read      = W * H * 2 * 60                  B/s
write bandwidth    = pixels_written_max * 2 * 60      B/s
1 Mbit             = 1e6 bits
```

### Framebuffer RAM (estimated)

| k | resolution | single buffered | double buffered | fits 2 Mbit | fits 4 Mbit | fits 8 Mbit |
|---|---|---:|---:|---|---|---|
| 1 | 480x270 | 2.074 Mbit | 4.147 Mbit | NO | yes | yes |
| 2 | 960x540 | 8.294 Mbit | 16.589 Mbit | NO | NO | NO |
| 4 | 1920x1080 | 33.178 Mbit | 66.355 Mbit | NO | NO | NO |

framebuffer RAM = W * H * 16 bits (RGB565). Doubled for a
double-buffered design, where the CPU writes one buffer while
the display scans the other out. 1 Mbit = 1e6 bits. 8 Mbit is
the largest block-RAM budget HD_EXPERIMENT.md §6 considers.

### Memory bandwidth (estimated)

| k | resolution | scan-out read | write (worst frame) | write : scan-out |
|---|---|---:|---:|---:|
| 1 | 480x270 | 15.55 MB/s | 40.33 MB/s | 2.59x |
| 2 | 960x540 | 62.21 MB/s | 161.32 MB/s | 2.59x |
| 4 | 1920x1080 | 248.83 MB/s | 645.27 MB/s | 2.59x |

scan-out read bandwidth = W * H * 2 * 60 bytes/s (the display
must re-read every pixel every frame). Write bandwidth =
pixels_written_max * 2 * 60 bytes/s. The ratio is the overdraw
the measured games actually have: the write side is dominated
by redrawn pixels, not by the resolution.

### Resources a native-HD asset set would need (computed, not drawn)

| asset (4-bit, 2 pixels/byte) | today 480x270 | 2x density 960x540 |
|---|---:|---:|
| hero frame 96x120 | 5,760 B | — |
| hero frame 192x240 | — | 23,040 B |
| hero, 8-frame cycle | 46,080 B | 184,320 B |
| one tile 64x64 | 2,048 B | — |
| one tile 128x128 | — | 8,192 B |
| full-width parallax strip 480x270 | 64,800 B | — |
| full-width parallax strip 960x540 | — | 259,200 B |

bytes = W * H * 4 / 8. Against today's budgets:

| | bytes | share of 256 KB ROM | share of 64 KB RAM |
|---|---:|---:|---:|
| today's hero cycle (8 frames) | 46,080 B | 17.6% | 70.3% |
| HD hero cycle (8 frames) | 184,320 B | 70.3% | 281.2% |
| today's full-width strip | 64,800 B | 24.7% | 98.9% |
| HD full-width strip | 259,200 B | 98.9% | 395.5% |
| HD hero frame | 23,040 B | 8.8% | 35.2% |
| today's tile | 2,048 B | 0.8% | 3.1% |
| HD tile | 8,192 B | 3.1% | 12.5% |

Budgets are the machine's today: 256 KB ROM (262,144 B), 64 KB RAM (65,536 B).

Where each byte is charged (`programs/link.ld`): a
`static const` asset table lands in `.rodata` and so costs **ROM**
only — the video device draws it straight from that address,
which is what the golden games do today. An initialised table
in `.data` is charged **twice**: its stored image sits in ROM,
and crt0 copies it into RAM, where it lives from then on. So
the ROM column is the primary denominator for asset bytes; the
RAM column is what the same bytes cost *if* they also have to
be resident, out of a 64 KB that also carries `.bss` and the
stack. RAM is a ceiling, not a free budget.

The framebuffer is in neither: SPEC.md section 5 has the device
drawing into its own RGB565 buffer, priced in the *Framebuffer
RAM* table above and absent from `arcade1 info`'s guest memory
map (rom 262144, ram 65536, mmio 4096).
